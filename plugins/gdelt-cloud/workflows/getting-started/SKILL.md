# Getting Started

Infer the user's intended result and scope. Choose one likely useful first step and state time-window or geography assumptions. Ask before an ambiguous identity join or a consequential unresolved choice. After answering, offer one or two relevant follow-ups: inspect a linked Story, examine nearby facilities, refine a country window, or preview a Monitor. Explain what each adds; avoid a tool tour. Use structured GDELT Cloud data first; schema-only help needs no data calls.

Discover one relevant domain with `<domain>_tool_list`, then batch promising names through `<domain>_tool_get`. Discovery is free, local and unmetered. Reuse a schema already known in the conversation. Call with tool-specific arguments nested in `tool_arguments`. Read calls use `_tool_call`; state changes use `_tool_write` only when authorized.

Core discovery accepts `section`: news, identity, countries, situations, monitors. Omit it for the whole catalog. Prefer unified entity identities, facilities and country context when they answer the task. Physical sites use the separate `facilities_tool_list`, `facilities_tool_get`, `facilities_tool_call` group; it is not nested in `gdelt_cloud_tool_list`. Use `facilities_search` for the public facility record, then specialist `energy_tool_*` for deeper source records. Use specialist registries for deeper native records; an identity match is not proof of ownership or a supply relationship. Preserve source-native IDs when moving between datasets.

During the launch transition, an installed plugin can connect to an older server. Treat the connected descriptors as authoritative: use unfiltered discovery if `section` is absent and omit `response_mode` if unsupported. Read the plugin's packaged workflows locally rather than assuming older servers expose these new skill URIs. Never switch connection URLs implicitly.

Choose `response_mode="compact"` for conversation or `"full"` for builders needing the bounded API response. Compact results retain IDs, citations, coverage, applied filters and pagination; `_mcp_projection` describes omitted detail. Full does not fetch more pages. Never interpret a partial window or missing coverage as zero activity.

Make returned GDELT Cloud Event, Story, entity and facility links the main navigation in an answer, with explicit text links retained beside any map or visual. Show the useful returned metrics alongside them, preserving their meaning, uncertainty and coverage. Use publisher/document links when the user needs underlying reporting; our record links remain the default citations for records and derived metrics. dataset credits such as GEM accompany registry facts rather than replacing facility links. Never construct a public URL from an ID. For a visual chat brief, request `include_images=true` and `include_entity_images=true` where supported and use up to three returned images/icons with attribution. Do not fetch extra records solely for decoration; text remains complete without images and sizing is client-dependent. Reuse the evidence already returned; a compact projection is not a reason to repeat successful searches with smaller limits.

Supporting web research is optional: orientation for a GDELT-supported task, corroboration, or source-page extraction. Supply purpose and brief task_context. Basic depth, at most five search results, three extraction URLs; at most two searches and one extraction batch per task. Stop sooner when sufficient. Do not use this service for standalone web research or replace unavailable structured evidence with web results. Entitlement failures remain explicit.

Account help opens website navigation only. Before connection, signup/subscription recovery belongs in the website/OAuth flow. Installed/imported skills are release snapshots; refresh them when upgrading.

Read the relevant package next: building (`skill://building-with-api/SKILL.md`), news and countries (`skill://news-country-research/SKILL.md`), counterparties and assets (`skill://counterparties-assets/SKILL.md`), Situations and Monitors (`skill://situations-monitors/SKILL.md`). Via MCP, read `skill://<package-name>/SKILL.md` using resources/read or the read_resource tool. In an installed plugin, read the matching local `workflows/<package-name>/SKILL.md`.

Research stays in the client's native conversation: linked record titles, short paragraphs, sparse meaningful emoji, compact Markdown comparison tables and native charts when useful and supported. Never open an app block for Events, Stories, Situations, entities, facilities, maps or metric charts. Favor the four core Event metrics (magnitude, systemic importance, propagation potential, market sensitivity) and category/subcategory; do not display coding confidence. Avoid wide tables, repeated record lists and decorative icons in every cell. Use returned coordinates/precision for maps if the client can plot data; do not turn news events into business/place listings or invent map URLs.

Use up to three returned images or avatars with attribution, beside their linked record. On unified identity search, imagery is opt-in: set include_images=true for a visual brief/profile; ordinary identity resolution need not request it. A portrait/logo is identity context, not a photo of the reported event. Markdown image syntax only: HTML and width attributes may appear as literal text. Native font, color, favicon treatment and image size belong to the client; never promise compact pixel dimensions or claim an image rendered just because its URL was returned. Returned image URLs are candidates, not verified-live images. If blocked, retain the title/link and evidence; do not fetch an unrelated replacement.

App blocks are reserved for account/signup/subscription navigation and Monitor workflows. Use `gdelt_cloud_monitor_form` when setting up an editable Monitor, with the arguments discovered for `preview_monitor`. It previews via the same authenticated API and never saves by itself. Ordinary `preview_monitor` calls return data for native chat without opening a form. Existing Monitor reads and authorized changes remain available through the normal wrappers.
